# ZeTer Media Converter — проверка после изменений

## Всегда
```bash
python tools/verify_project.py
```
Проверяет:
- compile всех Python-файлов;
- импорт публичного `VideoToAudioConverter`;
- сохранение 149 методов converter API (включая уведомление о готовых файлах);
- актуальность generated `CODE_MAP/CODE_INDEX`;
- recursive source identity для вложенных feature packages.

## После структурных изменений
```bash
python tools/generate_code_index.py
python tools/verify_project.py
```

## Targeted owner lookup
```bash
python tools/find_owner.py "ключевые слова изменения"
```

## Runtime smoke
Регрессии уведомлений: `python -B tools/test_completion_notification.py`.
`python -B tools/test_completion_notification.py --gui` дополнительно создаёт
изолированное настоящее окно Tkinter с искусственными путями, без инициализации
приложения и производственных логов. Проверяет постоянную видимость, topmost,
рабочую область монитора, переход без закрытия, крестик, повтор и прокрутку.
Вызов Проводника в автоматических проверках подменён: фактическое выделение файла
проверить вручную на короткой задаче MP3 и MP4. Сверить положение поверх другого
приложения, при свёрнутом главном окне и на другом мониторе. При сбое прислать
снимок уведомления и соответствующий итог задачи из «Логи проблем».

```bash
python "ZeTer Media Converter.py"
```
Это проверяет создание Tkinter UI, но не доказывает FFmpeg workflows.

## FFmpeg/audio/video изменения
Автоматические регрессии: `python tools/test_audio_regressions.py`.
Тесты загружают owner-классы без GUI и производственных логов; все media и записи
создаются в отдельной временной папке. Нужны `ffmpeg` и `ffprobe` в PATH.
Проверяются отказ публикации, резервное копирование, неправильные длительности,
ошибка/отмена fallback и реальное преобразование двухдорожечного видео с проверкой
длительности декодированных samples и частоты выбранного звука, включая повтор.
Это не проверяет GUI, многочасовые курсы и восстановление после отключения питания.

Дополнительно проверяются отсутствие неполных частей в итоговой папке, отказ
перезаписи существующего имени, откат публикации набора и длительность каждой части.
Реальная разбивка короткого сигнала проверяет порядок двух тонов и число декодированных
samples по обе стороны границы частей при уменьшенном тестовом лимите.
`python tools/test_audio_run_regressions.py` проверяет восстановление управления после
ошибок диагностики запуска/завершения, повторный запуск и отсутствие ложного успеха.

На Windows с установленными `ffmpeg` и `ffprobe` проверить только затронутые claims, минимум:
- короткий корректный media input;
- error/fallback input, если менялась error branch;
- cancel/timeout, если менялся subprocess lifecycle;
- повторный запуск того же folder/output;
- итоговые durations и <=10h limit, если менялась concat/split логика.

Проверяются также фигурные скобки в служебном заголовке FFprobe и внутри JSON-строк,
короткий MP3 меньше 1 КБ, полный путь короткое видео → MP3 → разбивка → декодирование,
а также отклонение небольшого файла, не содержащего аудио.

## Diagnostics/storage изменения
Проверить:
- `Логи проблем` остаются рядом с launcher в source mode;
- summary/problem/report ссылки существуют;
- bounded process logs и retention не сломаны;
- `diagnostics_integrity` не сообщает structural/semantic mismatch.
